# Pre-launch audit, 13 Nov 2026: 13 points

Base: `master` at `6cba305` (#306). This follows the 9 Nov go-live audit (`docs/golive-audit-2026-11-09.md`).
Every blocker it found in the code was fixed and live by 10 Nov (#285–#289). This audit covers the
22 PRs since then (#290–#306, about 12,800 backend lines), never audited before. It also re-checks
production: database, Railway, logs, alerts, backups, and where data lives.

**Method.** Production was read only, except for the changes listed under "Done 13 Nov". Four
reviewers each read one area end to end on `origin/master`:
- isolation and access;
- money, WhatsApp and AI actions;
- privacy and data flows;
- dependencies, secrets and hardening.

Each finding was re-read in the code before it went into a fix. Fixes went in four PRs, each with tests
that fail on the old code.

### In the code (next)

- Rate limits key on the caller-sent `X-Forwarded-For` hop. Needs a trusted-proxy rule that handles Vercel's proxy, not just "last hop".
- The property-enquiry form doesn't check the listings module or cap per tenant. The listings admin routes have no section rule.
- Marking a bank account private leaves its earlier lines in the books. A private viewer is chosen by a phone number the owner can edit.
- Smart Scanner: cloud reads aren't grounded against the page text; scans aren't checked for duplicates. Bank matches within 1% book the full invoice.
- The client page's "still to pay" total can disagree with its rows (rows are clamped at zero, the total isn't).
- No retention rule yet for `vula_chat_messages`, `vula_wa_outbound`, telemetry, email tables or uploads. No tenant-level erase or export.
- Storefronts: Next.js ≥ 15.5.28. vula_storefront allows images from any host. The off-the-hook admin cookie is the raw password.
- No CSP anywhere; HSTS not set explicitly.
- CI has no dependency scanning or SAST.
- react-router's fix needs v7.
